# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、修版与套色印制过程串成可追溯的本地记录，便于刻工与印制管事按套色序号协作。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 新增占用牌相关三张表，并为旧档做兼容补登：
  - `occupations`：一块版一行（主键即 `blockId`），记录当前两小时占用牌与完整牌历史；
  - `occupationOps`：领用/交回操作意向，主事务前先落盘，供关页重开对账恢复；
  - `workbenchDrafts`：版片编排台的序号、崩口操作草稿，去抖保存、关页前强制落盘。
- 已有刻工署名的旧版片在升级时补一张关闭态「历史占用」（`legacy`，在刻记 `expired`、已完成记 `returned`），不发新牌、不进刻工当班名单，不算新领取；刻工原 `activeBlockIds` 当班名单同步撤空，版片署名与状态原样保留。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入四类画稿、完整基础版片、四名刻工、印制批次与多条工序节点。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

### 领用占用牌规则

- 刻工在版片编排台「领用」一块版，即领得一张两小时有效的占用牌；一块版同时只认一张，两个窗口同时保存只会有一人成功，另一人收到占用冲突提示。
- 领用时版片转入「在刻」，刻工当班名单（负担）增加；名单始终以有效期内的占用牌为唯一事实来源。
- 两小时期满或主动「交回」（含标刻成）后，刻工名单撤下，版片仍算在刻，下一位可重新领用；同一刻工在期满前续领会换发新牌，旧牌留入历史。
- 领用/交回主事务写入中途失败（或关页）时，事务整体回滚到原占用、原版片状态与原名单；重开后自动对账，操作意向与序号/崩口草稿保留，可在页面提示处「按草稿继续领用」或「放弃草稿」。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号、标记刻成并记录崩口 |
| `/blocks/:id/nodes` | 工序节点时间线 | 推进或回退工序节点，登记操作人、时间与耗时 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，并逐版填写套色偏差 |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
